# 索引：向量模型切换

## 不原地重建

切换模型时**绝不**在活动索引上重建：那段时间里检索要么返回空，要么返回用新模型算的查询向量去比老模型的库——两个向量空间根本不可比。

正确做法是新建一个**阴影索引**，用新规格全量构建，构建完通过一致性检查再原子切换。活动索引在整个过程中持续服务。

## 指纹决定"同一个向量空间"

指纹由 `provider + model + dimensions + maxSequenceLength + revision` 算出。对云端模型，**endpoint 也参与指纹**：同一个模型名部署在两个服务商，产生的向量空间不同，不能被当成同一规格。

指纹相同就复用同一规格和同一个生成器实例，避免同一模型被加载多次。

## 切换会发生什么

1. 设置页保存新的默认规格。
2. 对每个还没用过该规格的知识库创建阴影索引（`activateWhenReady = true`）。
3. 后台构建 + 一致性检查。
4. 检查通过后切换到新索引，旧索引置为 `Retired`。

旧索引不删。保留它是为了"新模型效果更差"时能一键回滚。

## 切换后的常见困惑

- 检索结果变了不是 bug，是向量空间变了。
- 引用里的相似度不能跨模型比较，两个空间的余弦分数没有统一含义。
- 伴侣模块的记忆向量按指纹隔离，换模型后需要点一次"重建索引"，否则那些消息暂时只能按关键词召回。
