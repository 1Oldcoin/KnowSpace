# 索引：混合检索

## 为什么要混

向量擅长"说法不同但意思一样"，词面擅长"编号、URL、函数名这类精确串"。两类问题在同一批用户里都会出现，只做一路必然丢一半。

## 融合方式

两路各取候选，用 **RRF（Reciprocal Rank Fusion）** 合并，`k = 60`：

```
score(doc) = Σ 1 / (k + rank_i(doc))
```

RRF 只用排名不用分数，好处是两路的相似度尺度不同也无所谓——余弦相似度和 ts_rank 本来就没法直接相加。

## 候选规模

- 候选倍数 **3**：top-5 的请求，每路各取 15 条。
- 上限 **60** 条：再多融合收益趋近于零，而延迟线性上升。
- 去重按切片 ID：同一片被两路同时命中时分数相加（排名越靠前，加成越大）。

## 可选开关

`Retrieval:HybridEnabled` 关掉后只跑向量。这个开关存在是为了**对照实验**，不是为了给用户当性能旋钮——关掉它一般只会更差。

## 已知短板

- 中文分词用的是 `simple` 配置（按空白和标点切），不做词干和同义词。所以"重试"和"重试次数"能匹配，但"重试"和"再次尝试"不能。
- 数字类的问法（"第几次"）词面几乎帮不上忙，因为问题里没有那个数字。
- 两路都召回不到时，融合也无能为力——这属于语料本身没有答案。
