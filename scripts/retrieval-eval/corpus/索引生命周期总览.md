# 索引生命周期总览

## 四个概念

- **规格（spec）**：用哪个模型，指纹唯一。
- **索引（index）**：某个知识库用某个规格算出来的一整套向量。
- **绑定（binding）**：知识库当前倾向用哪个规格。
- **活动索引（active index）**：检索真正读的那一个。

四者分开是为了让"换模型"变成一个可回滚的操作，而不是一次不可逆的迁移。

## 一次完整生命周期

```
内容变更 → outbox 事件 → 增量重放（或全量重建）
        → 构建完成 → 一致性检查 → 质量分 → 激活
        → 旧索引退役 → 延迟清理
```

## 各类操作的落点

| 操作 | 落在哪一步 |
| --- | --- |
| 上传/删除资料 | 增量重放 |
| 换向量模型 | 新建阴影索引 + 全量重建 |
| 改切片策略 | 全量重建 |
| 效果不好要回去 | 切指针（回滚），不重建 |

## 不变的原则

1. 活动索引永不原地重建。
2. 构建失败不影响正在服务的索引。
3. 每一步都留下可读的原因，而不是一个通用错误码。

具体的阈值、抽样数量、保留策略写在各自的章节里，这里不重复，避免两份说明互相矛盾。
