# 插件运行时：健康检查

## 探活方式

健康检查只有一个动作：`ping`。它是 MCP 方言里的标准方法，实现成本极低，插件作者不需要额外写代码。

## 节奏与判定

- 间隔 **30 秒**发一次 `ping`。
- 单次 `ping` 的超时是 **5 秒**（不是 `tools/call` 的 60 秒）。
- 连续 **3 次**没有正常响应，状态改为 `Unhealthy`。
- 状态变 `Unhealthy` 之后**不会自动重启**。这一点是刻意的：自动重启会把"插件有内存泄漏"这类真问题掩盖成"偶尔慢一下"。
- 恢复：等到一次成功的 `ping` 就自动回到 `Running`。

## 为什么用连续 3 次

单次失败太常见：GC 停顿、磁盘抖动、系统在跑杀毒扫描都能让一次 `ping` 超过 5 秒。连续 3 次意味着大约 90 秒持续无响应，这个时长才真正值得报警。

## 和"调用失败"的关系

`ping` 成功不代表 `tools/call` 一定成功——某个工具自己写崩了也会返回错误，但进程还活着。反过来，`ping` 失败说明进程整体不健康，此时调用它只是浪费 60 秒超时。

所以调用前如果状态是 `Unhealthy`，宿主直接返回失败，不再尝试。

## 界面表现

插件列表的"状态"列会显示 `Running` / `PermissionRequired` / `Unhealthy` / `Crashed` / `Degraded`。`Unhealthy` 时会附带最后一次成功 `ping` 的时间。
