# 任务：排队与并发

## 默认并发

调度器默认开 **2 个**槽位（`Jobs:Concurrency`）。每个槽位独立领取任务、独立 `ExecutionContext`——一个槽位里跑挂的异常不会污染另一个。

为什么不默认更高：任务大多是"解析资料 + 算向量"，本质是 CPU 与磁盘密集。并发开大只会让每个任务都变慢，还更容易撞上内存峰值。

## 优先级

三档：`high` / `normal` / `low`。领取时按（优先级，入队时间）排序，同级先进先出。

`low` 不是"永远排最后"：只要没有高优先级的待领取任务，低优先级照样会被领走。这是为了避免饥饿。

## 队列上限

待领取 + 运行中合计超过 **1000** 条时，新的入队请求直接失败，返回"任务队列已满"。这个上限是**保护**，不是容量规划：真到这个量级说明有东西在死循环投递。

## 同类型顺序

同一个 `type` 的任务默认可以并行（比如两份资料同时解析）。需要串行的类型在注册处理器时声明 `concurrency = 1`。

## 观察方法

任务中心页显示的"运行中 / 排队中"就是槽位与队列的实时读数。如果"运行中"长期小于并发数，而"排队中"很大，说明有任务卡在租约过期的回收里，去看租约那一章。
