# 任务中心总览

## 它解决什么

资料解析、插件同步这类工作可能跑几十秒到几分钟，不能挂在 HTTP 请求里。任务中心把它们变成可观察、可取消、可重跑的后台任务。

## 一次任务的一生

```
入队（Queued） → 被某个槽位领取（Running）
              → 进度推送 → 完成（Completed）
              → 失败则按退避重试 → 最终 Failed
```

中途可能出现两种异常路径：执行者消失（回收器接手，回队列）和用户取消（写标记，执行侧收尾）。

## 界面能看到什么

- 列表：类型、状态、进度、耗时、错误摘要
- 计数徽标：排队中 / 运行中 / 今日失败
- 详情：阶段、错误原文、重试与回收次数、幂等键
- 操作：取消、重跑

## 三个独立计数

`attempt`（自己失败的次数）、`recovery_count`（被执行者放弃的次数）、`priority`（领取顺序）。三者互不替代，混在一起看会得出错误结论。

## 这一篇不写数值

并发数、租约、退避曲线、保留天数都是可配置项，写在各自章节。总览里抄一份，只会在改配置之后变成两份互相矛盾的说法。
