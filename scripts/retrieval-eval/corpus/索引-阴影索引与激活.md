# 索引：阴影索引与激活

## 状态机

`Building` → `Ready` → `Active` → `Retired`，任何一步失败进 `Failed` 并记录 `failureReason`。

只有 `Active` 的索引参与检索。每个知识库在 `kb_active_indexes` 里有且只有一行指向当前活动索引，检索路由**单行原子读取**这一行，所以切换索引不需要锁。

## 激活的三个条件

1. 构建进度到 100%，且没有未处理的失败事件。
2. 一致性检查通过。
3. 质量分不低于 **90**。

三条都满足才切换。任何一条不满足，活动索引保持不变，阴影索引留在 `Ready` 等重试。

## 为什么"原子"

切换写的是同一个事务里的一行：更新 `kb_active_indexes` 的 `index_id` + 指纹 + 维度，同时把旧索引标 `Retired`。检索侧读到的永远是完整的一组（索引 + 指纹 + 维度），不会出现"新索引配老指纹"的瞬时不一致。

## 回滚

`POST /api/knowledge-bases/{id}/indexes/{indexId}/rollback` 把指定索引重新设为活动。回滚不做构建，直接切指针——前提是那个索引的向量还在。

## 清理

`Retired` 索引的向量保留一段时间后由清理任务删除。**默认不自动删当前和上一个活动索引**，因为回滚依赖它们。
