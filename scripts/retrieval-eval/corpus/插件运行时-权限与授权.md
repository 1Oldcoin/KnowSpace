# 插件运行时：权限与授权

## 五个权限词

清单里能声明的权限只有这些：

| 词 | 含义 |
| --- | --- |
| `network` | 允许出站网络连接 |
| `file-read` | 读授权目录 |
| `file-write` | 写授权目录 |
| `clipboard` | 读写剪贴板 |
| `process` | 启动子进程 |

生态里常见的别名会被归一化：`net.outbound` → `network`，`fs` → `file-read` + `file-write`，`proc` → `process`。归一化会作为警告透出，**认不出的权限词原样保留并直接报错**，不会静默忽略。

## 授权流程

安装后插件停在 `PermissionRequired` 状态，此时进程不会启动。用户在插件页勾选后，资源被授予、ACL 被写入，然后进程启动。撤销授权会让进程退出。

**改配置会重启进程**：配置是以环境变量注入的（MCP 只认环境变量，没有 `configure` 方法），改完必须重启才能生效，这一点在界面上有提示。

## 敏感度等级

权限不只是"有/没有"，还带副作用等级。`destructiveHint` 的能力在调用前要求确认；`readOnlyHint` 的能力不要求。等级既可以写在 `annotations` 里，也可以由清单里同名能力覆盖。

## 别做的事

- 不要给插件授整个用户目录。数据目录 + 插件目录就够，越权范围越大，泄露面越大。
- 不要指望"插件自己会守规矩"。权限的价值恰恰在于：插件不守规矩时代码也跑不出去。
