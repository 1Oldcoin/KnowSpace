# 插件运行时：崩溃恢复

## 什么算崩溃

进程非零退出、或收到信号被杀、或管道读写抛 `IOException`，都归到崩溃。**正常退出**（`shutdown` 之后自己退出）不算。

## 自动重启的边界

- 自动重启最多 **2 次**。
- 两次之间间隔 **10 秒**，给系统回收句柄的时间。
- 超过 2 次仍崩溃，状态改成 `Crashed`，不再自动重启，必须用户手动点"重启插件"。

为什么限制次数：无限重启会让一个必然崩溃的插件把 CPU 打满，而且用户永远看不到真正的原因。

## 崩溃记录

每次崩溃写一个 `crash-{timestamp}.json` 到插件目录，字段包括退出码、最后 200 行 stderr、崩溃时正在执行的能力名、以及当时的内存占用。最多保留 10 份。

## 状态迁移

```
Running --崩溃--> Restarting --成功握手--> Running
                          └--再次崩溃--> Crashed
```

`Restarting` 期间调用会立即失败（`-32002 Plugin restarting`），不会排队等待——排队会让调用方白等 10 秒。

## 常见根因

- 插件把 stdout 关了（协议通道断掉，看起来像崩溃）
- 内存超限被系统杀掉
- 下载大文件时把临时目录写满

诊断时先看 `crash-*.json` 里的 stderr 尾部，比看宿主日志快。
