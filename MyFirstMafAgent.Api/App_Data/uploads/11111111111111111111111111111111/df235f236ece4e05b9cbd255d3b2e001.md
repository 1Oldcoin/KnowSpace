# 便携版 PostgreSQL 17.9 + pgvector 0.8.7（Windows x64）

一个**免安装、免依赖**的 PostgreSQL 向量数据库二进制包，用于嵌入 .NET API + Electron 桌面应用。  
全部产物都在本目录下，已通过端到端自测。

| 项目         | 值                                                                   |
| ---------- | ------------------------------------------------------------------- |
| PostgreSQL | **17.9**（EnterpriseDB 官方 Windows x64 binaries，非安装包）                 |
| pgvector   | **0.8.7**（从源码用 MSVC 编译，与 17.9 头文件严格匹配）                              |
| 平台         | Windows 10/11 x64，**无需**安装 VC++ 运行时（已内置）                            |
| 精简后体积      | **65.2 MB**（1105 个文件）                                               |
| 压缩包        | **26.6 MB** — `dist\pgsql-portable-17.9-pgvector-0.8.7-win64.zip`   |
| 自测状态       | `scripts\self-test.ps1` 全部通过（initdb → 启动 → 建向量表 → HNSW 索引 → 重启数据仍在） |

## 2. 快速开始

```powershell
cd C:\Users\zhs\Desktop\PG

# 1) 初始化数据目录（只做一次）：建库 appdb + 自动装好 vector 扩展
powershell -ExecutionPolicy Bypass -File scripts\pg.ps1 init

# 2) 启动（默认 127.0.0.1:55440，用户 postgres / 密码 postgres）
powershell -ExecutionPolicy Bypass -File scripts\pg.ps1 start

# 3) 验证
powershell -ExecutionPolicy Bypass -File scripts\pg.ps1 psql -Sql "select extversion from pg_extension where extname='vector'"

# 4) 停止
powershell -ExecutionPolicy Bypass -File scripts\pg.ps1 stop
```

连接串：

```
Host=127.0.0.1;Port=55440;Username=postgres;Password=postgres;Database=appdb
```

跑一遍完整验收（用 %TEMP% 里的临时库，不碰你的数据）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\self-test.ps1
```

### 向量检索示例

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE docs (
    id    bigserial PRIMARY KEY,
    body  text,
    emb   vector(768)              -- 维度按你的 embedding 模型定
);

-- HNSW 索引：余弦距离。建议先插数据再建索引
CREATE INDEX docs_emb_idx ON docs USING hnsw (emb vector_cosine_ops);

-- 最近邻查询（<=> 余弦距离，<-> L2，<#> 内积）
SELECT id, body, emb <=> $1 AS distance
FROM docs
ORDER BY emb <=> $1
LIMIT 10;
```

## 3. 嵌入 .NET API + Electron

两个示例都已经写好，并**在本机实测通过**，细节看各自的 README：

- **.NET 端**：`samples\dotnet\` — Npgsql 9 + `Pgvector.Npgsql`，两种向量传参方式（强类型 vs 字符串）都有示例。
- **Electron 端**：`samples\electron\` — `pg-lifecycle.js`，负责选空闲端口、首次运行 initdb、启动/等待就绪/退出时优雅关闭。

发布时的关键点：

1. `dist\pgsql` 放进 Electron 的 `extraResources`（**不要**打进 asar，`postgres.exe` 无法从 asar 里执行）：
   ```json
   // electron-builder
   "extraResources": [{ "from": "vendor/pgsql", "to": "pgsql" }]
   ```
   运行时路径：`path.join(process.resourcesPath, 'pgsql', 'bin', 'postgres.exe')`。
2. **数据目录放 `%LOCALAPPDATA%\<YourApp>\pgdata`**，不要放 `Program Files`（无写权限）。
3. **不要以管理员权限运行**：`postgres.exe` / `initdb.exe` 检测到提权令牌会直接拒绝启动  
   （`Execution of PostgreSQL by a user with administrative permissions is not permitted`）。  
   如果你的 .NET 进程清单里写了 `requireAdministrator`，数据库就起不来。
4. 端口**动态选**（先试绑定，占用就换），别用 5432 —— 用户机器上很可能已有 PostgreSQL。
5. 首次启动要 initdb（本机约 3 秒），期间给个启动画面；之后启动约 1 秒。

## 4. 踩过的坑（都已在本包里解决，改造时别踩回去）

### 4.1 `pg_ctl` 把父进程挂死 —— 最坑的一个

`pg_ctl start` 会拉起 `postgres.exe`，后者**继承 `pg_ctl` 的标准输入输出句柄**。  
如果父进程是用「管道」接收输出（Node 的 `spawn` 默认 `stdio: 'pipe'`、.NET 的  
`RedirectStandardOutput = true`、PowerShell 的 `&` 或 `>` 重定向、`Start-Process -RedirectStandardOutput`），  
那么 `postgres.exe` 会一直持有管道写端 → 父进程永远等不到 EOF → **卡死**。

现象：命令不返回、进程管理器里 `postgres.exe` 活得好好的、日志显示已启动成功。

正确做法：把 `pg_ctl` 的 stdio 直接指向**文件**（或 `ignore`）：

```js
// Node / Electron：stdout/stderr 都指向日志文件描述符
const logFd = fs.openSync(logFile, 'a');
spawn(pgCtl, ['-D', dataDir, '-l', logFile, '-w', 'start'],
      { stdio: ['ignore', logFd, logFd] });
```

```powershell
# PowerShell：必须借 cmd 的 > 重定向（PS 自己的 > 也是管道，同样会挂）
cmd /d /s /c "`"$pgctl`" -D `"$dataDir`" -l `"$log`" -w start > `"$out`" 2>&1"
```

> 注意：`pg_ctl` 自己的输出不能和 `-l` 写同一个文件，Windows 会报  
> “The process cannot access the file because it is being used by another process”。  
> 用两个文件，或把 `pg_ctl` 的输出直接丢掉。

### 4.2 端口被占用时报的是 "Permission denied"，不是 "address in use"

PostgreSQL 用 `SO_EXCLUSIVEADDRUSE` 绑端口，端口被占时报：

```
LOG:  could not bind IPv4 address "127.0.0.1": Permission denied
FATAL:  could not create any TCP/IP sockets
```

**这台机器上就有两个占用**：已安装的 PostgreSQL 18 服务（`postgresql-x64-18`）占着 **5432**，  
另有一个本地实例（`~/.pg0/installation/18.1.0`，MyFirstMafAgent 用）占着 **55432**。  
所以 `initdb` 的默认配置（`port=5432`, `listen_addresses='localhost'`）**直接起不来**。

本包默认用 **55440**，并显式写死 `listen_addresses = '127.0.0.1'`  
（`localhost` 会先试 IPv6 `::1`，多一层不确定性）。换端口只需 `-Port 55441`。

### 4.3 日志文件不能放在数据目录里

如果把 `pg_ctl -l` 的日志放进 PGDATA，崩溃恢复时 PostgreSQL 会对数据目录做 fsync，  
撞上你还开着的日志文件 → `could not open file "./log/postgres.log": sharing violation`，  
重试 30 秒后启动超时。本包把日志放在数据目录**同级**的 `logs\`。

### 4.4 其他

| 坑                     | 说明                                                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 提权运行                  | 管理员令牌下 `postgres.exe` 拒绝启动，见 3.3                                                                                                       |
| VC++ 运行时              | `postgres.exe` 依赖 `VCRUNTIME140.dll`，EDB 包里**不带**。本包已把 `vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll` 放到 `bin\`，目标机器无需装 Redist |
| 中文/空格路径               | `initdb` 的数据目录建议纯 ASCII、无空格，避免编码问题                                                                                                     |
| 杀毒软件                  | 会锁 `postgres.exe` 所在目录，导致启动慢或失败；发布时把安装目录加白名单                                                                                           |
| 备份                    | 用 `pg_dump.exe -Fc`，恢复用 `pg_restore.exe`；直接拷数据目录必须停库后拷                                                                                 |
| `wal_level=minimal`   | 本包为单机嵌入式场景设置，省 WAL 体积；若以后要做逻辑复制/备库，改回 `replica`                                                                                        |
| 语言包                   | 只保留了 `zh_CN` / `zh_TW` 消息（省 20 MB），其余回退英文                                                                                              |
| plpython/plperl/pltcl | DLL 在，但需要额外 Python/Perl/Tcl 运行时，默认不可用，不影响使用                                                                                            |
| 改 `pg.ps1`            | 要改默认端口就改 `[int]$Port = 55440`，改完记得 `destroy -Yes` 再 `init`（端口写在 `postgresql.conf` 里）                                                   |

## 5. 重建 / 升级

三个脚本串起来就是完整流水线，改版本号即可重跑。

```powershell
# 1) 换 PostgreSQL 版本：改 URL 里的版本号（17.9-1 → 17.10-1 / 18.4-1 ...）
curl -L -o downloads\postgresql-17.9-windows-x64-binaries.zip `
  https://get.enterprisedb.com/postgresql/postgresql-17.9-1-windows-x64-binaries.zip

# 2) 解压（zip 里自带一层 pgsql\）
tar -xf downloads\postgresql-17.9-windows-x64-binaries.zip -C build\pgsql

# 3) 编译并安装 pgvector（需 VS 的 C++ x64 工具集，脚本会自动找 vcvars64）
scripts\build-pgvector.cmd build\pgsql\pgsql build\pgvector-master

# 4) 裁剪出 dist\pgsql
powershell -ExecutionPolicy Bypass -File scripts\make-dist.ps1

# 5) 验收
powershell -ExecutionPolicy Bypass -File scripts\self-test.ps1

# 6) 打包
tar -a -c -f dist\pgsql-portable-17.9-pgvector-0.8.7-win64.zip -C dist pgsql
```

**换 pgvector 版本**：把新版源码解压到 `build\pgvector-master`（或任意目录，第二个参数传进去），  
重跑第 3 步。`build-pgvector.cmd` 用的是 `PGROOT` 里的 `include\` + `lib\postgres.lib`，  
所以**必须用同一份 PG 包编译**，ABI 才严格一致。

**版本对应关系**：pgvector 0.8.x 支持 PostgreSQL 13–18（`META.json` 要求 ≥ 15.0）。  
本包 17.9 + 0.8.7 是最稳的组合；要上 PG 18 只需换 zip 重跑，无需改脚本。
